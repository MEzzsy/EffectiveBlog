1. 动态内存与智能指针

1.1. 介绍

智能指针定义在memory头文件中。智能指针的作用是管理一个指针，避免申请的空间在函数结束时忘记释放，造成内存泄漏这种情况的发生。

1.2. auto_ptr

std::auto_ptr 是 C++98 提供的智能指针，最大的特点是：复制会转移所有权，而不是共享所有权。

std::auto_ptr<int> p1(new int(10));
std::auto_ptr<int> p2 = p1;

// 所有权转移给 p2，p1 变为空

这种复制语义很反直觉，例如把 auto_ptr 传给函数或放进容器时，原指针可能意外失去所有权。此外，它使用 delete 释放资源，不能管理动态数组。因此在C++11 中被弃用。应使用 std::unique_ptr 代替

void testAutoPtr() {
  SY_LOG("测试1");
  {
    std::auto_ptr<ClasstAutoPtr> p(new ClasstAutoPtr());
    SY_LOG("p ptr=%p", p.get());
  }
  SY_LOG("测试2");
  {
    std::auto_ptr<ClasstAutoPtr> p1(new ClasstAutoPtr());
    SY_LOG("p1 ptr=%p", p1.get());
    std::auto_ptr<ClasstAutoPtr> p2;
    p2 = p1;
    SY_LOG("p1 ptr=%p", p1.get());
    SY_LOG("p2 ptr=%p", p2.get());
  }
}

测试1
ClasstAutoPtr()
p ptr=0x600003f64050
~ClasstAutoPtr()
测试2
ClasstAutoPtr()
p1 ptr=0x600003f64050
p1 ptr=0x0
p2 ptr=0x600003f64050
~ClasstAutoPtr()

此时不会报错，p2 剥夺了 p1 的所有权，但是当程序运行时访问 p1 将会报错。所以 auto_ptr 的缺点是：存在潜在的内存崩溃问题。

1.3. unique_ptr

unique_ptr 是独占所有权智能指针，通过禁止复制、允许显式移动来避免 auto_ptr 隐式转移所有权的问题。

std::unique_ptr 是 C++11 引入的独占所有权智能指针，它的核心特点是：同一时间只能有一个 unique_ptr 拥有该资源。

auto p1 = std::make_unique<int>(10);

// std::unique_ptr<int> p2 = p1;  // 错误：不能复制
auto p2 = std::move(p1);          // 正确：转移所有权

转移后，p1 变为空，资源由 p2 管理。当 p2 离开作用域时，对象会被自动释放。

主要特点：

  • 不支持复制，只支持移动；
  • 所有权关系明确，运行时开销很低；
  • 支持管理单个对象和动态数组；
  • 可以通过自定义删除器管理文件、句柄等资源；
  • 应优先使用 std::make_unique 创建。
auto object = std::make_unique<int>(10);
auto array  = std::make_unique<int[]>(100);

1.3.1. 转移操作

  • std::move：标准、推荐的所有权转移方式。
  • release()：只放弃所有权并返回裸指针，不会释放资源。
  • reset()：释放当前资源，然后接管一个新指针；它本身不是“转移操作”。
auto p1 = std::make_unique<int>(10);
std::unique_ptr<int> p2;

p2.reset(p1.release());

执行后，资源归 p2，p1 为空。但这种写法不推荐，因为裸指针会短暂暴露，而且自定义删除器的状态不会随指针转移。

1.3.2. 传递unique_ptr参数和返回unique_ptr

不能拷贝unique_ptr的规则有一个例外：我们可以拷贝或赋值一个将要被销毁的unique_ptr。最常见的例子是从函数返回一个unique_ptr：

unique_ptr<int> clone(int p) {
    //正确：从int*创建一个unique_ptr<int>
    return unique_ptr<int>(new int(p));
}

还可以返回一个局部对象的拷贝：

unique_ptr<int> clone(int p) {
    unique_ptr<int> ret(new int(p));
    // ...
    return ret;
}

对于两段代码，编译器都知道要返回的对象将要被销毁。在此情况下，编译器执行一种特殊的“拷贝”。

1.3.3. 小结

unique_ptr实现独占式拥有概念（unique_ptr不支持赋值），保证同一时间内只有一个智能指针可以指向该对象。它对于避免资源泄露特别有用。

1.4. shared_ptr

std::shared_ptr 是 C++11 引入的共享所有权智能指针，多个 shared_ptr 可以共同管理同一个对象。

它通过引用计数管理资源：

  • 复制时，强引用计数加一；
  • 销毁或 reset() 时，强引用计数减一；
  • 最后一个 shared_ptr 销毁时，所管理的对象被释放。

1.4.1. 创建shared_ptr

普通对象优先使用 make_shared；需要自定义删除器时使用裸指针构造；需要共享已有对象时复制 shared_ptr；从独占所有权转换时移动 unique_ptr。

创建 shared_ptr 的常见方式如下。

创建方式 是否新建控制块 所有权效果 适用场景
make_shared 是 创建新对象并取得所有权 默认首选
裸指针构造 是 接管裸指针 自定义删除器等特殊需求
reset 是 释放原资源并接管新指针 更换管理对象
复制 shared_ptr 否 共享已有控制块，引用计数加一 共享所有权
移动 shared_ptr 否 转移已有所有权，引用计数通常不变 所有权传递
从 unique_ptr 移动构造 是 独占所有权变为共享所有权 所有权模式升级
weak_ptr::lock() 否 成功时共享已有控制块 安全获取临时强引用
allocate_shared 是 类似 make_shared，支持分配器 自定义内存分配

使用 make_shared

auto p = std::make_shared<MyClass>(10);

通常只进行一次内存分配，将对象和控制块一起分配。性能和异常安全性较好，是最推荐的方式。

使用裸指针构造

std::shared_ptr<MyClass> p(new MyClass(10));

对象和控制块通常分别分配。主要用于需要自定义删除器的情况：

std::shared_ptr<FILE> file(
    std::fopen("test.txt", "r"),
    [](FILE* f) {
        if (f) {
            std::fclose(f);
        }
    }
);

使用 reset

std::shared_ptr<MyClass> p;
p.reset(new MyClass(10));

如果 p 原来管理对象，会先减少原对象的引用计数，再接管新对象。也支持删除器：

p.reset(new MyClass, customDeleter);

一般创建对象时仍优先使用 make_shared。

复制和移动

复制会共享所有权，引用计数加一：

auto p1 = std::make_shared<int>(10);
std::shared_ptr<int> p2 = p1;

移动会转移这个 shared_ptr，原指针变为空，引用计数通常不增加：

std::shared_ptr<int> p2 = std::move(p1);

从 unique_ptr 转换

auto unique = std::make_unique<int>(10);
std::shared_ptr<int> shared = std::move(unique);

资源由独占所有权变为共享所有权，unique 变为空。反向不能直接转换，因为无法确定共享对象是否只有一个所有者。

从 weak_ptr 获取

std::weak_ptr<int> weak = shared;

if (auto p = weak.lock()) {
    // 对象仍然存在，p 是有效的 shared_ptr
}

lock() 成功时会返回共享同一个控制块的 shared_ptr；对象已经销毁时返回空指针。

使用 allocate_shared

auto p = std::allocate_shared<MyClass>(allocator, 10);

它类似于 make_shared，但允许指定内存分配器，适用于内存池等场景。

安全规则

最重要的安全规则是：不要用同一个裸指针分别创建多个 shared_ptr。

int* raw = new int(10);

std::shared_ptr<int> p1(raw);
std::shared_ptr<int> p2(raw); // 错误：两个独立控制块，会重复释放

正确方式是复制已有的 shared_ptr：

std::shared_ptr<int> p1(new int(10));
std::shared_ptr<int> p2 = p1;

此外，不要让普通指针和 shared_ptr 同时承担同一个对象的所有权。

int* raw = new int(10);
std::shared_ptr<int> p1(raw); // 不推荐：raw 和 p1 并存，容易混淆所有权

delete raw; // 错误：p1 之后还会再次释放该对象

裸指针一旦交给 shared_ptr 接管，就不能再手动释放，也不能再用它创建其他独立的智能指针。需要访问原始指针时，可以使用 get()，但得到的指针只用于非拥有式访问，不能延长对象的生命周期：

auto p1 = std::make_shared<int>(10);
int* raw = p1.get(); // 可以观察和访问，但不能 delete raw

1.4.2. shared_ptr内存结构

即auto p = std::make_shared<MyClass>(10);和std::shared_ptr<MyClass> p(new MyClass(10));的区别

shared_ptr 需要管理两部分数据：

  1. 实际对象；
  2. 控制块，其中保存强引用计数、弱引用计数、删除器等信息。

例如：

std::shared_ptr<MyClass> p(new MyClass);

执行过程可以理解为：

MyClass* raw = new MyClass;  // 第一次分配：对象
std::shared_ptr<MyClass> p(raw); // 第二次分配：控制块

内存结构大致如下：

shared_ptr p
   ├── 指向 MyClass 对象 ──> [ MyClass 对象 ]
   └── 指向控制块 ────────> [ 强引用计数、弱引用计数、删除器等 ]

对象和控制块位于两块独立的堆内存中，因此通常发生两次内存分配。

而 make_shared：

auto p = std::make_shared<MyClass>();

可以预先知道对象类型和控制块大小，通常一次性分配：

shared_ptr p
   └──> [ 控制块 | MyClass 对象 ]

所以 make_shared 通常具有以下优势：

  • 只进行一次内存分配；
  • 内存局部性更好；
  • 创建速度通常更快；
  • 异常安全性更好。

不过，两种方式的内存释放时机也有所区别。存在 weak_ptr 时：

shared_ptr(new T)：
强引用归零 → 对象内存立即释放
弱引用归零 → 控制块内存释放

make_shared<T>()：
强引用归零 → 对象析构
弱引用归零 → 对象和控制块所在的整块内存释放

因此，make_shared 管理特别大的对象且长期存在 weak_ptr 时，整块内存可能延迟释放。

这里使用“通常”是因为 C++ 标准主要规定行为，并不完全强制具体内存布局；但主流标准库基本都会这样实现。

1.5. weak_ptr

std::weak_ptr 是 C++11 引入的弱引用智能指针。weak_ptr是一种不控制所指向对象生存期的智能指针，它指向由一个shared_ptr管理的对象。

核心特点：

  • 不增加对象的强引用计数；
  • 不会阻止对象被销毁；
  • 不能通过 * 或 -> 直接访问对象；
  • 需要调用 lock() 转换为 shared_ptr 后才能安全访问（weak_ptr没有get接口）；
  • 主要用于解决 shared_ptr 的循环引用问题。

1.5.1. 基本用法

auto shared = std::make_shared<int>(10);
std::weak_ptr<int> weak = shared;

std::cout << shared.use_count(); // 1，weak 不增加强引用计数

访问对象前应调用 lock()：

if (auto p = weak.lock()) {
    std::cout << *p; // 对象仍然存在
} else {
    std::cout << "对象已经销毁";
}

lock() 的结果：

  • 对象存在：返回一个有效的 shared_ptr，强引用计数暂时加一；
  • 对象已销毁：返回空的 shared_ptr。

1.5.2. 判断对象是否销毁

if (weak.expired()) {
    std::cout << "对象已经销毁";
}

不过不要先调用 expired()，再假定对象一定存在：

if (!weak.expired()) {
    // 此时对象仍可能被其他线程销毁
}

需要访问对象时，直接使用 lock() 更安全。

1.5.3. 解决循环引用

如果两个对象互相使用 shared_ptr：

struct B;

struct A {
    std::shared_ptr<B> b;
};

struct B {
    std::shared_ptr<A> a;
};

引用关系可能形成环：

A ──shared_ptr──> B
A <──shared_ptr── B

即使外部的 shared_ptr 都被销毁，两个对象的强引用计数仍不为零，因此无法释放。

可以将其中一侧改为 weak_ptr：

struct B;

struct A {
    std::shared_ptr<B> b;
};

struct B {
    std::weak_ptr<A> a;
};

这样 B 只观察 A，不会增加 A 的强引用计数，从而打破循环。

1.5.4. 对象与控制块的释放

当强引用计数归零时，对象被销毁；如果仍然存在 weak_ptr，控制块会继续存在。等弱引用也全部消失后，控制块才会被释放。

2. 指针和引用的区别

对比项 指针 引用
本质 保存地址的对象 已有对象或函数的别名
绑定 可改变指向，除非指针本身为 const 初始化后不可重新绑定，赋值会修改被引用对象
空值 可以为空，也可能悬空 没有合法空引用，但可能悬空
const const T* 限制通过指针修改对象；T* const 限制改指向 const T& 限制通过引用修改对象
sizeof 指针类型的大小 被引用类型的大小（适用于对象引用）
传参 T* 形参复制指针值 T& 形参直接绑定实参对象

引用的绑定规则由语言规定，具体实现由编译器决定。

3. 堆和栈区别

对比项 栈 堆
用途 通常保存局部变量、部分参数和调用信息 提供动态内存
管理 通常随作用域和函数调用自动分配、回收 由程序管理，可交给智能指针或容器自动释放
大小 每个线程的栈通常较小 可用空间通常较大，受进程地址空间和资源限制
分配特点 通常开销小，按栈帧回收，无堆式外部碎片 分配策略取决于分配器，可能产生碎片

局部变量和参数也可能放在寄存器中。栈的增长方向、传参和清理规则取决于平台与调用约定；堆单次分配的虚拟地址连续，多次分配不保证相邻。

4. new｜delete，malloc｜free区别

都可以用来在堆上分配和回收空间。new /delete 是操作符，malloc/free 是库函数。

执行 new 实际上执行两个过程：

  1. 分配未初始化的内存空间(malloc)
  2. 使用对象的构造函数对空间进行初始化
  3. 返回空间的首地址。

如果在第一步分配空间中出现问题，则抛出 std::bad_alloc 异常，或被某个设定的异常处理函数捕获处理。

如果在第二步构造对象时出现异常，则自动调用 delete 释放内存。

执行 delete 实际上也有两个过程：

  1. 使用析构函数对对象进行析构
  2. 回收内存空间(free)

以上也可以看出 new 和 malloc 的区别，new 得到的是经过初始化的空间，而 malloc 得到的是未初始化的空间。delete 和 free 同理，delete 不仅释放空间还析构对象。

为什么有了malloc/free 还需要 new/delete？ 因为对于非内部数据类型而言，光用 malloc/free 无法满足动态对象的要求。对象在创建的同时需要自动执行构造函数，对象在消亡以前要自动执行析构函数。由于 malloc/ free 是库函数而不是运算符，不在编译器控制权限之内，不能够把执行的构造函数和析构函数的任务强加于malloc/free，所以有了 new/delete 操作符。

5. 预处理，编译，汇编，链接程序的区别

  1. 预处理：展开头文件和宏，处理条件编译；GCC 中通常对应 .i（C）或 .ii（C++）。
  2. 编译：进行语法、语义分析和优化，生成目标架构的汇编代码，通常对应 .s。
  3. 汇编：将汇编代码转换为可重定位目标文件，通常为 .o，包含机器码、数据、符号和重定位信息。
  4. 链接：组合目标文件和库，解析符号、处理重定位，生成可执行文件或共享库；静态链接纳入所需库代码，动态链接保留共享库依赖，由装载器等在装载或运行时完成相应解析。

6. fork，exec，clone

以下示例各自保存为对应的 .cpp 文件。fork/exec 可在 Linux、macOS 运行；clone 示例针对 Linux/glibc（常见 x86-64、AArch64 平台）。前两例输出在本机 macOS 实测，clone 输出为 Linux 下的预期结果。

6.1. fork

fork函数产生一个和当前进程完全一样的新进程，在fork函数调用之后，新的任务将启动并和本任务一起从fork函数返回。但不同的是本任务的fork将返回新任务pid，而新任务的fork将返回0。（参考demo，test4）

fork产生新任务的速度非常快，因为fork并不复制原任务的内存空间，而是和原任务一起共享一个写时复制（Copy on Write，COW）的内存空间。所谓写时复制，指的是两个任务可以同时自由地读取内存，但任意一个任务试图对内存进行修改时，内存就会复制一份提供给修改方单独使用，以免影响到其他的任务使用。

6.1.1. 示例：父子进程分别修改变量

保存为 fork_demo.cpp：

#include <cerrno>
#include <cstdio>
#include <sys/wait.h>
#include <unistd.h>

int main() {
    int value = 10;
    pid_t pid = fork();
    if (pid == -1) { std::perror("fork"); return 1; }

    if (pid == 0) {
        value = 20;
        std::printf("child: pid=%ld, value=%d\n", (long)getpid(), value);
        std::fflush(stdout); // _exit 不刷新标准 I/O 缓冲区
        _exit(0);
    }

    int status = 0;
    while (waitpid(pid, &status, 0) == -1) {
        if (errno == EINTR) continue;
        std::perror("waitpid");
        return 1;
    }
    std::printf("parent: pid=%ld, child=%ld, value=%d\n",
                (long)getpid(), (long)pid, value);
    return WIFEXITED(status) ? WEXITSTATUS(status) : 1;
}

编译运行：

c++ -std=c++17 fork_demo.cpp -o fork_demo
./fork_demo

一次实测输出（PID 每次运行不同）：

child: pid=48819, value=20
parent: pid=48812, child=48819, value=10

子进程将 value 改为 20，父进程仍为 10，因为普通变量位于各自的私有地址空间。这里用 waitpid 等子进程结束后再打印父进程信息；fork() 本身不保证父子执行顺序。接口说明

6.2. exec

fork只能够产生本任务的镜像，因此须要使用exec配合才能够启动别的新任务。exec可以用新的可执行映像替换当前的可执行映像，因此在fork产生了一个新任务之后，新任务可以调用exec来执行新的可执行文件。

6.2.1. 示例：替换程序，PID 保持不变

保存为 exec_demo.cpp：

#include <cstdio>
#include <unistd.h>

int main(int argc, char* argv[]) {
    const char* path = argc > 1 ? argv[1] : "/bin/sh";
    std::printf("before exec: pid=%ld\n", (long)getpid());
    std::fflush(stdout); // exec 成功后，原程序的用户态缓冲区不再保留

    execl(path, "sh", "-c", "printf 'after exec: pid=%s\n' \"$$\"",
          static_cast<char*>(nullptr)); // 变参列表须以空指针结束

    std::perror("execl"); // 只有 exec 失败才会执行到这里
    return 1;
}

编译运行：

c++ -std=c++17 exec_demo.cpp -o exec_demo
./exec_demo

一次实测输出：

before exec: pid=48813
after exec: pid=48813

第二行由替换后的 /bin/sh 输出，$$ 表示该 shell 的 PID。两行 PID 相同，说明 exec 替换了程序，没有创建新进程；成功时不会执行后面的 perror。接口说明

传入不存在的路径可观察失败分支：

./exec_demo /no/such/program

一次实测输出（程序退出码为 1）：

before exec: pid=48822
execl: No such file or directory

6.3. clone

fork和exec通常用于产生新任务，而如果要产生新线程，则可以使用clone。使用clone可以产生一个新的任务，从指定的位置开始执行，并且（可选的）共享当前进程的内存空间和文件等。如此就可以在实际效果上产生一个线程。

6.3.1. 示例：控制是否共享内存

保存为 clone_demo.cpp：

#ifndef _GNU_SOURCE
#define _GNU_SOURCE
#endif
#include <cerrno>
#include <csignal>
#include <cstdio>
#include <cstdlib>
#include <sched.h>
#include <sys/wait.h>

int child_main(void* arg) {
    *static_cast<int*>(arg) = 20;
    return 7; // glibc clone 包装函数将此值作为子进程退出状态
}

int main(int argc, char*[]) {
    const bool shared = argc > 1; // 传入参数时启用 CLONE_VM
    int value = 10;
    constexpr std::size_t stack_size = 1024 * 1024;
    char* stack = static_cast<char*>(std::malloc(stack_size));
    if (!stack) { std::perror("malloc"); return 1; }

    int flags = SIGCHLD | (shared ? CLONE_VM : 0);
    pid_t pid = clone(child_main, stack + stack_size, flags, &value);
    if (pid == -1) {
        std::perror("clone");
        std::free(stack);
        return 1;
    }

    int status = 0;
    while (waitpid(pid, &status, 0) == -1) {
        if (errno == EINTR) continue;
        std::perror("waitpid");
        return 1;
    }
    std::free(stack); // 子进程结束后才能释放它使用的栈
    if (!WIFEXITED(status)) return 1;
    std::printf("shared=%d, value=%d, child_exit=%d\n",
                shared ? 1 : 0, value, WEXITSTATUS(status));
}

在 Linux 上编译：

c++ -std=c++17 clone_demo.cpp -o clone_demo

预期运行情况（本机 macOS 未实测）：

$ ./clone_demo
shared=0, value=10, child_exit=7

$ ./clone_demo shared
shared=1, value=20, child_exit=7
  • 关闭 CLONE_VM：子进程修改自己的变量副本，父进程仍读到 10。
  • 开启 CLONE_VM：共享地址空间，父进程等子进程结束后读到 20。
  • 本例设置 SIGCHLD，可用 waitpid 等待并读取退出状态；没有设置 CLONE_THREAD，两种情况都创建独立进程，共享内存不等于加入同一线程组。接口说明
